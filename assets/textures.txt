# SFPS material library -- edit freely, the dev build reloads this on save.
#
# A material is a list of ops run per pixel. Every number is an INTEGER with
# a fixed implied scale, so the parser needs no float handling at all.
# Whitespace and newlines are interchangeable: each opcode has a known arity,
# so the parser just reads that many integers and moves on.
#
#   t <name>              begin a material
#   base   r g b          fill colour, 0-255
#   brick  w h m          brick lattice: cell w x h, m px mortar joint
#   tint   r g b          per-brick colour spread, /255
#   grain  n              per-pixel noise, +-n/200
#   bevel  w lit shade    w px edge, lit%/100 top-left, shade%/100 bottom-right
#   mortar r g b n        joint colour 0-255 plus its own noise n/255
#   brush  sx sy amp      noise stretched by sx/100, sy/100, amplitude amp/100
#   blotch f amp          broad noise at frequency f/100
#   scratch thr gain      bright streaks above threshold thr/100
#   seam   p dark light   panel edges every p px
#   wood   r g b grain    sawn timber: warped bands, grain strength /100
#   check  size depth     diamond checkering, as cut into a grip
#   ribs   period depth   cooling ribs along a barrel
#   blue   n              pull toward blue-black gun bluing, 0-100
#   gloss  n              specular strength, 0-100 -- see below
#   proc   k s            no pixels at all: fragment shader k computes the
#                         surface from the UV, s/100 cells per unit -- see the
#                         procedural section at the end of this file
#   bump   n              relief: tilt the shading normal by the material's own
#                         brightness gradient, n/100. Procedural materials only
#                         -- see the relief note in the procedural section
#
# Ops that follow `brick` know which pixels are mortar, which is how a flat
# op list expresses "only inside a brick".
#
# GLOSS lives in the texture's alpha channel. Alpha was already there and
# unused, so per-pixel specular costs no extra texture, sampler or uniform.
# Anything without a `gloss` op stays matte, which is why brick needs no
# change and wood looks like wood. `check` also drops gloss in its cut
# grooves, so one material shines on the diamonds and not between them.

t brick
base 107 51 38          # clay body
brick 64 32 3           # course 64x32, 3px mortar joint
tint 56 26 18           # per-brick colour spread
grain 18                # +-0.09 per pixel
bevel 3 118 80          # lit 1.18 top-left, 0.80 bottom-right
mortar 107 107 112 26   # joint colour + its own noise

t metal
base 59 61 67           # dark gunmetal, faintly blue
brush 50 3 26           # grain stretched hard along x
brush 12 1 15           # second, coarser octave
blotch 2 15             # broad unevenness across panels
scratch 93 220          # sparse bright scratches
seam 64 50 110          # machined panel edges every 64px
gloss 55

# --- gun materials -------------------------------------------------------
#
# What makes a weapon read as a weapon is the contrast between these, not
# detail inside any one of them. A single material across the whole gun looks
# like a prop no matter how good that material is.

t blued                 # barrel: dark, tight, high shine
#
# Ops run in order and each one sees what the last left behind, so this reads
# top to bottom as a manufacturing sequence: rough stock, then the machining
# marks, then the bluing, then the wear that happened after.
base 52 54 60
brush 60 2 18           # sx 0.60 sy 0.02: noise stretched almost to a line,
                        # which is what makes it read as drawn-out machining
                        # rather than as dirt
ribs 34 22              # a vented rib along the barrel. `ribs` bands on x,
                        # and on the extrusion's skirt u runs ALONG the
                        # barrel, so the bands cross it the way a real rib
                        # does. This op existed and nothing used it.
blotch 3 10             # slow, broad variation so the bluing is not uniform
scratch 96 160          # sparser than bare steel -- bluing hides less wear
blue 70
gloss 85

t gunmetal              # the muzzle face: deliberately FLAT, not a pattern
#
# Darker than `blued` and almost featureless on purpose. This material exists
# to be UV-independent: it sits on the end face of the barrel, which the
# extruder textures as part of the perimeter skirt, so any pattern here would
# land at an arbitrary offset and read as a smear of barrel across the muzzle.
# A near-solid colour cannot be misplaced.
#
# `grain` is the one exception, and it is kept tiny. Absolutely flat colour
# reads as a hole cut in the gun rather than as metal -- a little noise gives
# the eye something to catch without being a pattern that can be mis-mapped.
base 30 31 35
grain 5                 # +-2.5/255, just enough to not look like a decal
blue 45                 # same bluing family as the barrel, a shade deeper
gloss 55                # duller than the barrel: a worn, powder-fouled crown

t steel                 # receiver: lighter, machined, visible panel edges
#
# The receiver is the part the eye actually rests on -- it is the widest flat
# face and it sits nearest the camera -- so it carries the most detail. Kept
# LIGHTER than the barrel on purpose: the contrast between the two is what
# separates them at a glance, and a receiver as dark as the bluing makes the
# whole gun read as one undifferentiated lump.
base 76 78 84
brush 40 3 22           # coarser and less stretched than the barrel: a
                        # machined block, not a drawn tube
blotch 2 14
seam 40 52 118          # panel edges. Tightened from 48px to 40px so a seam
                        # actually falls on the receiver at this UV scale
                        # instead of straddling it -- at uv 300 a 48px period
                        # put barely one edge across the visible face.
scratch 92 240          # bare steel wears brightly; this is the top layer,
                        # after the seams, so scratches cross the panel edges
                        # rather than being interrupted by them
gloss 70

t walnut                # stock and fore-end
#
# Warmer and lighter than `grip`, and deliberately so: the fore-end catches
# more light than the grip in the hand, and the two woods reading slightly
# differently sells them as separate pieces of timber rather than one
# extrusion that happens to bend.
wood 92 54 28 45
blotch 4 8              # broad tonal drift across the blank -- real timber is
                        # never one colour end to end, and this is what stops
                        # the grain looking printed on
scratch 97 90           # handling marks: high threshold, low gain, so they
                        # are a few faint scuffs and not a scoured surface
gloss 18                # oiled, not polished

t grip                  # walnut with checkering cut into it
#
# Darker stock than the fore-end, and the checkering is cut INTO it: `check`
# drops gloss to a quarter inside the grooves, so the diamonds catch light and
# the cuts between them stay dull. That gloss split is most of why real
# checkering reads as cut rather than as printed diamonds -- see the note at
# the top of this file.
wood 78 44 22 40
blotch 4 6              # subtler than the fore-end; the checkering is already
                        # busy and broad drift underneath it turns to mush
check 8 62              # tighter (9 -> 8) and deeper (55 -> 62). At uv 300 the
                        # old spacing was coarse enough on the small grip face
                        # to read as a lattice laid over the wood; tighter
                        # diamonds read as cut checkering at this size.
gloss 22

# --- procedural materials ------------------------------------------------
#
#   proc   k s          hand the surface to fragment shader k, s/100 pattern
#                       cells per UV unit
#
# These have NO pixels. The shader computes the surface from the UV, so it
# stays sharp with the player's nose against it, needs no mipmaps, and costs
# four uniforms instead of a 256x256 RGBA texture. `base` gives the shader its
# colour and `gloss` its specular strength -- the same two ops the pixel path
# already uses, so a material can be moved between the two by editing one line.
#
# Shader k:  1 brick   2 tile    3 panel   4 wood
#            5 hex     6 marble  7 rust    8 grid
#
# Keep this list in step with the PROC_* enum in src/render.h and the switch
# in procColour(); there is no way to share an enum with GLSL.


# --- relief ----------------------------------------------------------------
# `bump <n>` tilts the shading normal by the material's OWN brightness
# gradient, so mortar joints, panel seams and hex lattice lines catch light on
# one side and shade on the other as the player moves past them. There is no
# normal-map texture and no per-vertex tangent: the height is the pattern's
# luminance and the tangent frame is derived from the face normal, which works
# because world UVs here are a dominant-axis projection. See procNormal in
# src/render.c.
#
# The value is a percentage. It is a SLOPE, so what reads correctly depends on
# how deep the feature is meant to be, not on how dark it is: a mortar joint is
# a real recess and takes a lot, marble veining is a colour change in a flat
# polished surface and should take none at all.
#
# A material that does not mention `bump` stays perfectly flat, which is what
# every recipe written before this existed expects.
#
# `bump <n>`은 재질 *자신의* 밝기 기울기만큼 셰이딩 법선을 기울입니다. 덕분에 줄눈,
# 패널 이음매, 육각 격자선이 플레이어가 지나갈 때 한쪽은 빛을 받고 반대쪽은 그늘집니다.
# 노멀 맵 텍스처도 정점별 탄젠트도 없습니다. 높이는 패턴의 휘도이고 탄젠트 프레임은 면
# 법선에서 유도하는데, 이곳의 월드 UV가 지배적 축 투영이기에 가능합니다.
# src/render.c의 procNormal을 참조하십시오.
#
# 값은 퍼센트입니다. *기울기*이므로 올바르게 읽히는 값은 얼마나 어두운지가 아니라 그
# 요소가 얼마나 깊어야 하는지에 달려 있습니다. 줄눈은 실제로 파인 곳이라 큰 값을 받고,
# 대리석 무늬는 평평하게 연마된 표면의 색 변화이므로 전혀 받지 않아야 합니다.
#
# `bump`를 언급하지 않는 재질은 완전히 평평하게 유지되며, 이 기능이 생기기 전에 작성된
# 모든 레시피가 그것을 기대합니다.

bump 90                 # mortar is a real recess -- the deepest relief here

# No `bump`: veining is a colour change in a polished slab, not a recess.
# Bumping it would make the stone look eroded rather than cut.
# `bump` 없음: 무늬는 파인 곳이 아니라 연마된 판의 색 변화입니다. 요철을 주면
# 돌이 잘린 것이 아니라 침식된 것처럼 보입니다.

t prust
base 122 62 30

t pgrid
base 40 180 210
proc 8 150
# No `bump`: the grid lines are EMISSIVE, so their brightness is light coming
# out rather than a surface facing toward one. Differencing it would tilt the
# normal away from the glow, which is backwards.
# `bump` 없음: 격자선은 *발광*이므로 그 밝기는 표면이 광원을 향한 것이 아니라 빛이
# 나오는 것입니다. 이를 차분하면 법선이 발광에서 멀어지게 기울어져 반대가 됩니다.

# Molten rock. The base colour is the CRACK, not the crust -- the crust is
# near-black rock the shader supplies itself, and what the recipe chooses is
# what colour the glow between the plates is. Swap it toward green for acid or
# toward blue for something colder without touching the shader.
#
# No `gloss`: molten rock is not a mirror, and a specular highlight sliding
# over lava reads as wet plastic.
#
# 녹은 암석입니다. base 색상은 껍질이 아니라 *균열*입니다. 껍질은 셰이더가 자체적으로
# 제공하는 거의 검은 암석이며, 레시피가 고르는 것은 판 사이에서 빛나는 색입니다. 셰이더를
# 건드리지 않고 초록 쪽으로 옮기면 산성 웅덩이가, 파랑 쪽으로 옮기면 더 차가운 무언가가
# 됩니다.
#
# `gloss`가 없습니다. 녹은 암석은 거울이 아니며, 용암 위를 미끄러지는 스페큘러 하이라이트는
# 젖은 플라스틱처럼 보입니다.
t plava
base 235 96 22
proc 9 60

# --- the grapple's tether -------------------------------------------------
# A twisted hemp rope. `ribs` stripes along the recipe's local x axis, and the
# tether's ribbon UV runs its u (0..utile) along the rope's own length -- so
# the bands wrap around the rope as it stretches, the same way a real twisted
# rope's strands do. Drawn unlit (RD_SWATCH): a cable a metre from your face
# should not need to be lit to read as a cable.

t rope
base 168 128 74          # tan hemp
ribs 10 35                # the twist -- period 10px, 35% light/dark
grain 12                  # fibre noise
gloss 8                   # faint sheen, mostly matte

# --- imported surfaces ---------------------------------------------------
#
# Freedoom wall patches, brought across by assets/sprites/import-walls.py and
# baked by bake.ps1 into the same indexed data the monsters use.
#
# `image <tiles>` fills the buffer from the drawing that shares this
# material's NAME, repeated `tiles` times. The name is the key precisely so
# there is no second place for it to disagree: a material called wall_brick
# fetches wall_brick and nothing else can be written.
#
# 2 tiles because the source is 128 and the buffer is 256. Any other number
# would land the wrap somewhere other than the buffer edge, and a seam that is
# not on the edge is a seam you can see.
#
# THE OPS AFTER `image` ACT ON THE IMAGE, which is the whole reason the door is
# one drawing rather than three: the key colour is a tint, not a bitmap.
#
# Freedoom 벽 패치이며, assets/sprites/import-walls.py가 가져오고 bake.ps1이 몬스터와
# 같은 인덱스 데이터로 굽습니다. `image <tiles>`는 이 재질의 *이름*과 같은 그림으로 버퍼를
# 채웁니다. 이름이 키인 이유는 어긋날 두 번째 장소를 만들지 않기 위해서입니다.
# 원본이 128이고 버퍼가 256이므로 2입니다. 다른 수는 되감김을 가장자리가 아닌 곳에
# 떨어뜨리며, 가장자리가 아닌 이음매는 눈에 보이는 이음매입니다.
# `image` 뒤의 연산은 이미지에 작용합니다. 문이 그림 셋이 아니라 하나인 이유가 그것입니다.

image wall_brick 2

t wall_stone
image wall_stone 2

t wall_rough
image wall_rough 2

t wall_metal
image wall_metal 2
gloss 30

t wall_plain
image wall_plain 2
